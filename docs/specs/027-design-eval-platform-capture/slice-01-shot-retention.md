## Slice 027-01 — shot retention + ledger visibility

**Goal:** Keep every design-eval run's app screenshots instead of clobbering
them, and record each shot's path in that run's ledger row — so a low fidelity
score is inspectable (open the exact image servo judged) rather than a number to
trust. Applies to every capture mode, web included.

**DoR:**
- ✅ Current behaviour probe-verified (2026-08-21): app shots write
  `base_dir/shots/app-<id>.png` with a fixed name, overwritten each run
  (`score.py:161-176`); `ledger.jsonl` carries per-screen rows with no shot
  path; there is no `report.md` (`main()` prints only the composite,
  `score.py:423`).
- ✅ Coupling probe-verified: `_judge_cli` cwd's to `app_png.parent.parent`
  (`score.py:222`), so app shots must stay exactly one directory under
  `base_dir` — retention must not deepen the path (use a stamped filename in
  `shots/`, not a per-run subdirectory).
- ✅ No new dependency; no ADR needed (shots are unfrozen outputs, not part of
  the frozen definition).

**Acceptance Criteria:**

1. **Runs no longer clobber shots.** After two consecutive live-capture runs of
   the same frozen eval, `base_dir/shots/` retains **two** distinct app
   screenshots per screen (unique per run), not one overwritten file. Filenames
   stay directly under `shots/` (path depth unchanged, preserving the
   `_judge_cli` cwd contract).
2. **The ledger points at the shot it judged.** Each live-capture ledger row's
   per-screen entry carries a `shot` field: a path (relative to `base_dir`) to
   the exact PNG that screen was judged on, and that path resolves to a real
   file on disk.
3. **No capture → no shot, honestly.** A run where no browser ran (the
   fake-scores / offline arm) records `shot: null` per screen — present but
   null, mirroring the `not_captured` provenance token; never a misleading path.
4. **Web scoring is otherwise unchanged.** The composite value, the frozen-hash
   validation, the `env_error`-on-failure contract, and the 0/1/2 oracle
   contract are untouched; the change is additive (a stamped shot filename + one
   new per-screen ledger field).

**Anti-horizontal-phasing check:** After this slice lands, a user running
design-eval can open the exact screenshot behind any per-screen score, for any
past run in the ledger, in every capture mode — end-to-end observable value, not
scaffolding for a later slice.

**Deferred (candidate for refinement-todo):** unbounded on-disk growth of
`shots/` across many loop iterations. This slice retains-not-clobbers; a
keep-last-N (or keep-milestones) cap is a follow-up, noted so it isn't a silent
gap. Git handling (track scores, keep raw shots local) is tracked separately in
GitHub #29's shared-plumbing.
