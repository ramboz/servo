## Slice 048-02 — refreeze-needs-fresh-regression

**Goal:** When an eval that has a regression set is re-frozen with a changed
judge fingerprint, the freeze requires a test-split regression record for the
new fingerprint against the current set — or an explicit acknowledgement
recorded as unaudited — and stamps the result on the approval. The numbers are
shown, never enforced; score time is untouched.

**DoR:**
- ✅ [ADR-0053](../../decisions/adr-0053-judge-regression-rescore.md) Accepted;
  048-01 DONE (the set, the fingerprint and the bound record).
- ✅ Re-probed: the three freeze paths (`eval_authoring.py:1290-1320`,
  `design_eval.py:237-296`, `content_fidelity.py:115-142`) and design-eval's
  `reviewed` / `self_approved` provenance, the pattern this slice mirrors
  (`design_eval.py:256-289`).

**Acceptance Criteria:**

1. **No set, no change.** Freezing an eval with no regression set behaves
   byte-identically to today on all three freeze paths.
2. **A changed fingerprint needs a fresh record.** For an eval with a regression
   set whose judge fingerprint differs from the one stamped at its last approval
   (or that has never been approved), freeze looks for a `mode: regression`,
   `split: test` record whose fingerprint and set hash match the config being
   frozen. With none, freeze refuses with an `EnvError` that names the command
   to run (`audit <eval> --regression`) and the acknowledgement flag.
3. **Freshness, not a pass mark.** A matching record lets freeze proceed
   whatever its metrics or recommendation say. Freeze prints the metrics and the
   recommendation, and stamps `regression_audit` (record timestamp, fingerprint,
   set hash, metrics, recommendation) on the config beside the other approval
   fields — outside `definition_hash`.
4. **Explicit acknowledgement.** `--acknowledge-no-regression` (or its
   environment-variable twin, mirroring design-eval's
   `SERVO_DESIGN_EVAL_ACK_EXCLUSIONS`) lets freeze proceed and stamps
   `regression_audit: {"status": "unaudited", ...}`. It is never silently
   upgraded to audited.
5. **Only judge changes trigger it.** A re-freeze that leaves the judge
   fingerprint unchanged (for example, only the eval's dataset cases changed)
   needs no new record and keeps the last `regression_audit` stamp as it was.
6. **Score time unchanged.** For every fixture above, the installed component's
   score, `oracle.sh` and `gate.py` results are identical before and after the
   stamp; `validate_freeze` ignores the stamp. The refinement-todo deferral
   "Judge-audit → composite gating" is untouched.
7. **Docs.** The eval-authoring, design-eval and content-fidelity `SKILL.md`
   freeze sections describe the check, the acknowledgement, and that it does not
   gate on the numbers. Surface-tested.
